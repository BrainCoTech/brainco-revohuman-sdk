# 08 容器运行

源码包的 `docker/` 目录提供一键构建脚本 `install.sh`、Docker 镜像的构建文件和启动脚本 `run.sh`。
镜像里按《01-环境安装与系统要求》的步骤装好了 ROS 2 Humble、Tracker 驱动 libsurvive、RevoHuman SDK、
ROS 2 包和三维可视化环境；主机上只需要装 Docker 和一条 Tracker 设备规则。

以下情况适合用容器：主机不是 Ubuntu 22.04；不想在主机上安装 ROS 2 与 Python 依赖；需要在多台主机上得到完全相同的环境。
容器里的命令、目录布局与手册其他各章相同，本章只讲容器特有的部分。

## 1. 主机要求

| 项目 | 要求 |
|---|---|
| 操作系统 | 64 位 Linux（x86_64 或 aarch64） |
| Docker | 23.0 或更新（构建时默认使用 BuildKit）；建议 25 或更新，容器起来之后插拔手套不用重建容器（见第 6 节） |
| 账户 | 一个有 `sudo` 权限的普通用户，并且在 `docker` 组里；**不要用 root 运行容器** |
| 磁盘 | 镜像约 2.6 GB；录制数据另计，见《04-数据录制》 |
| 网络 | 构建镜像时需要访问 Ubuntu 软件源、ROS 软件源、PyPI 与 GitHub；构建好之后运行不需要网络 |
| USB、蓝牙 | 与《01-环境安装与系统要求》第 1 节相同 |

## 2. 主机准备

以下三步在主机上做一次。用第 3 节的 `install.sh` 构建时，Docker 的安装、`docker` 组与 Tracker 设备规则由脚本检查，
缺哪项补哪项（执行前询问），可以直接跳到第 3 节；本节是手动做法。

**Docker 用户组。** 按 Docker 官方文档装好 Docker 后，把当前用户加入 `docker` 组：

```bash
sudo usermod -aG docker $USER
```

加组之后要注销并重新登录（或重启）才生效。执行 `docker info` 不报 `permission denied` 即可。

**Tracker 设备规则。** 容器通过主机的设备节点访问 Tracker，这条规则必须装在**主机**上（与《01》第 6 节的规则相同，装过的可跳过）：

```bash
sudo tee /etc/udev/rules.d/81-revohuman-tracker.rules > /dev/null <<'RULES'
# Vive Tracker（USB 有线，28de:2300）
SUBSYSTEM=="usb", ATTRS{idVendor}=="28de", ATTRS{idProduct}=="2300", MODE="0666"
KERNEL=="hidraw*", SUBSYSTEM=="hidraw", ATTRS{idVendor}=="28de", ATTRS{idProduct}=="2300", MODE="0666"
RULES
sudo udevadm control --reload-rules && sudo udevadm trigger
```

已插着的手套单元装完规则后重新插拔一次。

**蓝牙。** 只有在容器里配对、标定基站时才用到（见第 7 节）。按《03-基站使用与配对》第 2 节确认主机的蓝牙服务在运行、适配器已打开。

主机上**不需要**把用户加入 `dialout` 组：`run.sh` 会把手套串口所属的组自动加给容器里的用户。

## 3. 构建镜像

把发布文件放进同一个目录（《01》第 2 节，下文仍以 `~/revohuman-release` 为例）。

**一键构建。** 解开源码包，在 `docker/` 目录里执行 `install.sh`：

```bash
cd ~/revohuman-release
tar xzf revohuman-0.1.1-bundle.tar.gz
cd revohuman-0.1.1/docker
./install.sh
```

国内网络加 `--mirror cn`（Ubuntu、ROS 2、PyPI 都改用阿里云镜像）。脚本依次执行六步，每步打印结果：

1. 核对发布文件：按 `SHA256SUMS` 逐个校验两个 wheel 与源码包。缺文件、没下载完、文件损坏、`SHA256SUMS` 不是这个版本的，都会指出是哪个文件。
2. 检查 Docker：没装时用 `apt` 安装；当前用户不在 `docker` 组时加入（本次运行先临时生效，注销重新登录后长期生效）；
   确认 Docker 服务在运行、版本够新，连的是本机的 Docker。Docker Desktop、rootless 模式、开启 userns-remap 的 Docker
   与 Podman 接不了手套或用户号对不上，脚本会直接说明，不往下构建。
3. Tracker 设备规则：主机上没有让所有用户都能读写 Tracker USB 设备的规则（`SUBSYSTEM=="usb"`、`MODE="0666"`）时安装，
   内容与第 2 节相同。只放开 hidraw 节点、或权限没有放开给所有用户的规则不算。
4. 构建前检查：磁盘空间、基础镜像（必须是 Ubuntu 22.04），以及软件源能否访问。当前 shell 里设了 `http_proxy` 等代理变量时，构建也走这个代理。
5. 构建镜像，`USER_UID` / `USER_GID` 自动取当前用户的。
6. 检查镜像：在镜像里执行与《01》第 10 节相同的检查，确认容器里写出的文件属主是当前用户；再用 `run.sh` 实际创建一个检查用的容器、
   在里面执行一条命令，通过后立即删除这个容器。

最后打印 `镜像 revohuman:0.1.1 已就绪` 和下一步要执行的命令。

- 用普通用户执行，**不要加 `sudo`**。需要 `sudo` 的步骤（安装 Docker、加入 `docker` 组、安装 Tracker 设备规则）执行前逐项询问；
  加 `-y` 不询问直接执行，加 `--skip-host-setup` 则不改动主机、只检查与构建，加 `--dry-run` 只检查并打印要执行的命令。
- 某一步失败时，脚本说明原因和处理办法后退出；改好后重新执行即可。镜像已经用同一批发布文件、同一个基础镜像为当前用户构建过时
  不重复构建，只重跑第 6 步的检查；要强制重新构建加 `--rebuild`。基础镜像在上次构建之后重新拉取过时，脚本会提示，同样加 `--rebuild`。
- 从之前的版本升级时，之前版本创建的容器如果还在后台运行，里面运行的仍是之前版本的程序。脚本结尾会提示
  `容器 revohuman 用的是另一个版本的镜像 …`，确认容器里没有正在运行的程序后执行 `./run.sh --restart`，换成新构建的镜像。
- 全部输出另存一份日志（`~/.local/state/revohuman-docker/install-<时间>.log`，开头会打印路径），需要技术支持时请附上它。
- 全部选项见 `./install.sh --help`。

**手动构建。** 不用脚本时，校验发布文件、解开源码包后，在存放发布文件的目录里构建：

```bash
cd ~/revohuman-release
sha256sum -c SHA256SUMS
tar xzf revohuman-0.1.1-bundle.tar.gz
docker build -f revohuman-0.1.1/docker/Dockerfile \
    --build-arg USER_UID=$(id -u) --build-arg USER_GID=$(id -g) \
    -t revohuman:0.1.1 .
```

国内网络访问软件源较慢时，加上镜像源参数：

```bash
docker build -f revohuman-0.1.1/docker/Dockerfile \
    --build-arg USER_UID=$(id -u) --build-arg USER_GID=$(id -g) \
    --build-arg UBUNTU_MIRROR=http://mirrors.aliyun.com \
    --build-arg ROS_APT_MIRROR=https://mirrors.aliyun.com/ros2/ubuntu \
    --build-arg ROS_GPG_URL=https://mirrors.aliyun.com/rosdistro/ros.key \
    --build-arg PIP_INDEX_URL=https://mirrors.aliyun.com/pypi/simple/ \
    -t revohuman:0.1.1 .
```

说明：

- 首次构建需要 10～20 分钟，主要花在下载上，视网络而定。构建时按主机架构自动挑选对应的 wheel，并逐个核对 `SHA256SUMS`；
  最后一步执行与《01》第 10 节相同的检查，任何一项不通过构建就会失败，不会产出有问题的镜像。
- **`USER_UID` / `USER_GID` 必须是运行容器的那个用户的**（上面的 `$(id -u)`、`$(id -g)`）。
  挂载目录的属主、设备的占用检查都按用户号判断，`run.sh` 发现不一致时会拒绝启动并提示重新构建。
  `install.sh` 自动取当前用户的值。同一台主机有多个用户要用容器时，每个用户各构建一份，用不同的镜像名区分
  （`install.sh --tag 名字` 或 `docker build -t 名字`），之后用 `./run.sh --image 名字` 进入。
- 构建只用到发布目录里的两个 wheel、源码包和 `SHA256SUMS`，目录里的其他文件不会被送进构建。

## 4. 进入容器

```bash
cd ~/revohuman-release/revohuman-0.1.1/docker
./run.sh
```

第一次执行时 `run.sh` 在后台创建并启动一个名为 `revohuman` 的容器，然后进入其中的 shell，终端打印：

```text
已启动容器 revohuman（数据目录：/home/<用户名>/revohuman-data；插拔手套不用重建容器）
```

Docker 低于 25 时，这一行列出的是创建容器时插着的手套串口，例如 `（手套串口：/dev/ttyACM0 /dev/ttyACM1；数据目录：…）`，
并另外提示插拔手套之后要 `./run.sh --restart`（见第 6 节）。

容器会一直在后台运行。**再开一个终端执行 `./run.sh`，进入的是同一个容器**，
所以手册里需要两个终端的场景（例如《05》的 `revohuman-live` 加可视化、《06》的节点加查看话题）照常用两个终端各执行一次 `./run.sh`；
其中《05》的广播加可视化也可以用 `simulation/run_sim_docker.sh` 一条命令完成（见第 8 节）。

也可以不进 shell，直接在容器里执行一条命令：

```bash
./run.sh python3 -m revohuman doctor
./run.sh python3 -m revohuman product identify
```

进入容器后，接着按《02-硬件连接》第 3 节体检，之后各章的命令原样执行即可。
容器里已经加载好 ROS 2 与 RevoHuman 工作空间的环境，不需要再 `source`。以下几处与在主机上不同：

- 《02》第 3.1 节的 `ls -l /dev/ttyACM*`：Docker 25 及以上时，容器的 `/dev` 下没有手套串口（SDK 到 `/run/host/dev` 下找），
  这条命令报 `No such file or directory` 属正常，以 `python3 -m revohuman doctor` 的结果为准。
- 《03-基站使用与配对》：蓝牙的检查与开启在主机上执行，容器要用 `--ble` 创建，完整步骤见第 7 节。
- 手册里写到家目录（`~/…`）的脚本、录制文件、日志与截图，在容器里改放到 `~/data` 下，见第 5 节。
- 《09-时间戳同步》的 `chronyc tracking` 在主机上执行：容器用的就是主机的时钟，镜像里没有装 chrony。

`run.sh` 的选项：

| 选项 | 说明 |
|---|---|
| `--restart` | 删除正在运行的容器，重新创建后再进入。改了下面任何一个选项、重新构建过镜像之后要加它；Docker 低于 25 时，插拔过手套也要加它 |
| `--stop` | 停止并删除容器。数据与标定都在主机目录里，不受影响 |
| `--data 目录` | 挂到容器里 `~/data` 的主机目录，默认 `~/revohuman-data` |
| `--state 目录` | 标定、配置与运行状态的主机存放目录，默认 `~/.local/share/revohuman-docker` |
| `--ble` | 允许容器使用主机的蓝牙（第 7 节） |
| `--no-gui` | 不接主机的图形界面 |
| `-e 名=值` | 给容器加环境变量，可重复 |
| `--image 镜像`、`--name 名字` | 使用的镜像（默认 `revohuman:0.1.1`）与容器名（默认 `revohuman`） |
| `--dry-run` | 只打印要执行的 `docker` 命令，不执行 |

选项只在创建容器时生效。容器已经在运行、而这次给的选项与创建时不同，`run.sh` 会打印
`注意：容器 revohuman 是按另一组设置创建的…`，加 `--restart` 重建即可。
容器是用另一个镜像创建的（例如升级之前的版本，或同名镜像重新构建之前），`run.sh` 会打印
`注意：容器 revohuman 是用镜像 … 创建的…` 并说出是哪个镜像，同样加 `--restart`。
Docker 低于 25 时，容器创建之后插拔过手套，`run.sh` 会打印 `注意：容器 revohuman 创建之后插拔过手套…`，同样加 `--restart`。

## 5. 数据、配置与标定存放在哪里

容器里下面这几个目录挂载自主机，删除、重建容器都不影响其中的内容：

| 容器里 | 主机上 | 内容 |
|---|---|---|
| `~/data`（进入容器时的当前目录） | `~/revohuman-data` | 录制数据、自己写的脚本 |
| `~/.config/revohuman` | `~/.local/share/revohuman-docker/config/revohuman` | 基站白名单 `lighthouses.yaml`、手套组注册表 |
| `~/.config/libsurvive` | `~/.local/share/revohuman-docker/config/libsurvive` | 基站几何 `config.json` |
| `~/.local/state/revohuman` | `~/.local/share/revohuman-docker/state/revohuman` | Tracker 与基站的状态文件 |
| `~/.ros` | `~/.local/share/revohuman-docker/ros` | ROS 2 节点日志 |

**容器里其他位置的文件在 `--restart`、`--stop` 之后都会丢失。** 手册里写到家目录的文件，在容器里改写到 `~/data` 下：

- 《04-数据录制》的录制脚本保存为 `~/data/revohuman_record.py`，输出目录也放在 `~/data` 下，例如
  `python3 ~/data/revohuman_record.py ~/data/demo 10 2`；
- 《07-日志与错误码》第 2 节生成的 `revohuman-report.tgz`，执行完后 `cp ~/revohuman-report.tgz ~/data/`，在主机的 `~/revohuman-data` 里取；
- 其他章节里写到家目录的文件同样改到 `~/data` 下：《04》其余几个脚本与 `~/revohuman_data/…` 输出目录
  （例如 `~/data/demo/episode_001.mcap`）、《06》第 6 节录 bag 的目录（`~/revohuman_bags` 改成 `~/data/revohuman_bags`）、
  《07》第 1 节的 `~/revohuman-doctor.log`、《07》第 3 节的 `revohuman_notices.py` 及其输出
  （运行时第二个参数写成 `~/data/revohuman-notices.jsonl`）、
  可视化截图（`--snapshot ~/data/….png`）；
- 脚本可以在容器里用 `nano` 编辑，也可以在主机上直接放进 `~/revohuman-data`。

**配置与标定是容器专用的一份**，和主机上直接安装的 SDK（`~/.config/revohuman`、`~/.config/libsurvive`）互不影响。
主机上已经配对、标定过基站，想让容器直接沿用时，先停掉容器，再把主机上的三个目录拷贝过去：

```bash
cd ~/revohuman-release/revohuman-0.1.1/docker
./run.sh --stop
S=~/.local/share/revohuman-docker
mkdir -p $S/config $S/state
cp -a ~/.config/revohuman ~/.config/libsurvive $S/config/
cp -a ~/.local/state/revohuman $S/state/
```

之后在容器里执行 `python3 -m revohuman tracker status`，应与主机上看到的一致。
反过来，从未在主机上标定过的，直接在容器里按《03-基站使用与配对》配对与标定即可。
基站被移动过需要重新标定，这一点与在主机上运行没有区别。

## 6. 手套与 Tracker

- **手套**：Docker 25 及以上，`run.sh` 让容器直接看到主机上的手套串口，容器起来之后再插上、或插拔过的手套，
  在容器里照常可用，不用重建容器。容器里能打开的只有手套串口与 USB 设备，主机上的其他设备打不开。
  Docker 低于 25 时，`run.sh` 只能在创建容器时把当时插着的手套串口交给容器：**容器创建之后才插上、或插拔过的手套，容器里用不了**，
  执行 `./run.sh --restart` 重建容器即可（容器里没有正在运行的程序时再重建）。
  此时容器里的体检会列出这个手套单元，但注明节点不可用，并提示重建容器。
- **Tracker**：插拔之后不需要重建容器。`product identify` 里某只手没有 Tracker 序列号时，
  检查主机上是否装了第 2 节的 Tracker 设备规则；`run.sh` 创建容器时发现当前用户无权读写 Tracker，也会打印提示。
- **设备占用在容器内外是同一套**：同一只手套、同一组 Tracker 同一时间只能有一个程序使用，
  不论这个程序在容器里还是在主机上。例如主机上开着 `revohuman-live` 时，容器里的录制脚本同样报 `1102` / `1900`。
- **USB 电源管理**：容器里的 SDK 能读到手套的 USB 电源管理状态，但不能修改，与在主机上以普通用户运行相同。
  体检的「USB 拓扑与电源管理」一项显示 `autosuspend 已关` 即正常。

## 7. 基站：蓝牙、配对与标定

配对基站、标定前的信道检查需要蓝牙（《03-基站使用与配对》）。容器通过主机的蓝牙服务使用适配器，默认不接蓝牙，要用 `--ble` 创建容器。
只有配对基站用的 `revohuman-lighthouses` 会用到蓝牙；标定、启动前自查、录制、广播与可视化都不用。
下面是在容器里从头配对、标定的完整步骤，每一步输出的含义与出错时的处理见《03》的对应小节。

### 7.1 在主机上：确认蓝牙，带蓝牙重建容器

容器里没有运行 systemd，《03》第 2 节的蓝牙检查与开启命令要在**主机**的终端里执行：

```bash
systemctl is-active bluetooth
bluetoothctl show | grep Powered
```

应看到 `active` 与 `Powered: yes`，不是时按《03》第 2 节在主机上开启。然后带 `--ble` 重建容器并进入
（容器里没有正在运行的程序时再重建）：

```bash
cd ~/revohuman-release/revohuman-0.1.1/docker
./run.sh --restart --ble
```

### 7.2 在容器里：配对

确认容器里看得到蓝牙适配器、两只手套都已接好，再扫描基站，并写出白名单配置文件：

```bash
bluetoothctl show | grep Powered
python3 -m revohuman doctor
revohuman-lighthouses scan
revohuman-lighthouses init
```

`doctor` 应显示 `fail=0`。第一次扫描时还没有白名单，`scan` 最后会提示白名单不存在或没登记，属正常。
把要用的基站序列号填进白名单（填法见《03》第 4.3 节；基站多、分不清哪台是哪台时，先按《03》第 4.2 节让基站闪灯辨认）：

```bash
nano ~/.config/revohuman/lighthouses.yaml
```

这个文件挂载自主机的 `~/.local/share/revohuman-docker/config/revohuman/lighthouses.yaml`（第 5 节），
也可以在主机上用自己习惯的编辑器修改那个文件，两边是同一份。填好后检查能否被正确读出（不用蓝牙，立即返回）：

```bash
revohuman-lighthouses show
```

没有 `✗` 即为正确。

### 7.3 在容器里：标定与自查

标定要求 5 分钟内做过一次成功的扫描。确认两只 Tracker 的指示灯都是绿色（《03》第 1.2 节），先扫描：

```bash
revohuman-lighthouses scan
```

最后一行是 `✓ 白名单 N 台都扫到，信道无冲突；信道预检已刷新（5 分钟内有效）` 时，紧接着开始标定，戴着手套按《03》第 5.2 节走动。
提示同信道冲突时，在容器里按《03》第 4.5 节执行 `revohuman-lighthouses plan` 与 `revohuman-lighthouses apply --yes` 后再扫一次；
其他提示见《03》第 4.4 节的表格。

```bash
python3 -m revohuman tracker calibrate
```

最后一行是 `标定完成：在册基站均已解出：…` 即完成；失败或被拒时按《03》第 5.2 节末尾的表格处理。再打开一次 Tracker，把基站与位姿实际验一遍：

```bash
python3 -m revohuman tracker check --live
python3 -m revohuman tracker status
```

`check --live` 看到 `✓ S0 静态门 通过` 与 `✓ S1 起流后门（…）通过`，`status` 的 `基站几何` 一行为 `可用` 即可。
白名单与标定结果都存放在挂载自主机的目录里（第 5 节），之后删除、重建容器都不用重做。

标定完成后，可以在主机上执行 `./run.sh --restart` 换回不接蓝牙的容器（容器里没有正在运行的程序时再执行）。
继续使用带蓝牙的容器时，之后每次进入都要写 `./run.sh --ble`，否则 `run.sh` 会提示容器是按另一组设置创建的。
挪过基站、改过信道之后，从 7.1 起重做一遍。

## 8. 图形界面

三维可视化（《05-仿真与可视化》）的窗口显示在主机的桌面上：`run.sh` 默认把主机的图形界面与显卡交给容器，
在桌面上打开的终端里执行 `./run.sh` 即可，无需其他设置。可视化的目录与主机安装时相同：

```bash
cd ~/revohuman-release/revohuman-0.1.1/simulation
./run_viewer.sh --demo
```

接真手套时，也可以不进容器，直接在主机上用一条命令在容器里拉起广播与可视化窗口：

```bash
cd ~/revohuman-release/revohuman-0.1.1/simulation
./run_sim_docker.sh
```

用法与《05》第 4.1 节的 `run_sim_host.sh` 相同：先在后台启动广播、就绪后打开窗口；关闭窗口、按 `Ctrl+C` 或关掉终端时，
一并停止容器里由它启动的广播与可视化，容器本身继续在后台运行。另有 `--image`、`--name`、`--restart` 三个选项，与 `run.sh` 的同名选项相同；
容器里固定使用镜像自带的 SDK，不接受 `--venv`。全部选项见 `./run_sim_docker.sh --help`。
容器没在运行时，脚本先用 `run.sh` 创建它；数据目录、蓝牙等容器选项要先用 `run.sh` 设好。已经在容器里时，直接执行 `./run_sim_host.sh`。

- 容器里只带 Intel、AMD 显卡的驱动。窗口能不能用上显卡，要看主机的桌面由哪块显卡输出：
  - 桌面由 Intel/AMD 显卡输出：只有这两种显卡的主机，以及同时带 Intel/AMD 核显和 NVIDIA 独显、桌面仍由核显输出的笔记本。
    容器里的窗口用 Intel/AMD 显卡绘制，通常可达 60 帧。
  - 桌面由 NVIDIA 显卡输出：只有 NVIDIA 显卡的主机，以及切换成只用独显的笔记本。容器里的窗口照样能打开，
    但改由 CPU 绘制，不到 10 帧；启动时终端会打印 `libGL error: failed to load driver: nouveau`。
    这类主机请在主机上运行可视化（见下一条），主机上的窗口用 NVIDIA 显卡绘制，约 60 帧。
- 可视化只接收本机广播，**主机上的可视化可以显示容器里 `revohuman-live` 的数据**，反过来也一样：
  `run.sh` 让容器与主机使用同一个广播位置。所以可以只在主机上运行可视化、SDK 留在容器里：
  主机上只需要解开源码包并执行 `simulation/run_viewer.sh`（见《01》第 9 节），不必安装 SDK 与 ROS 2。
  容器里已经在广播时，在主机上执行 `simulation/run_sim_host.sh` 同样只打开窗口、不另起广播。
- 关闭窗口时终端会打印刷新率，例如 `[view] 窗口关闭：3580 帧 / 60.0s（59.7 fps）`。明显低于 60 时，
  说明窗口没用上显卡，同样改在主机上运行可视化（见上一条）。
- 通过 SSH 登录、没有桌面时，用《05》第 5 节的无窗口模式；`./run.sh --no-gui` 创建的容器不接图形界面。

## 9. ROS 2

容器与主机共用网络，ROS 2 话题在容器内外互通。`run.sh` 创建容器时把主机上的 `ROS_DOMAIN_ID`、`ROS_LOCALHOST_ONLY`、
`RMW_IMPLEMENTATION` 带进容器；在主机上改了这几个变量，要 `--restart` 重建容器才对容器生效。

《06-ROS2》的节点在容器里启动后，主机上装有 ROS 2 Humble 时可以直接 `ros2 topic list` 看到它的话题。

## 10. 常见问题

| 现象 | 处理 |
|---|---|
| `run.sh: 无法连接 Docker` | Docker 服务没启动，或当前用户不在 `docker` 组、加组后还没重新登录：见第 2 节 |
| `run.sh: 找不到镜像 revohuman:0.1.1` | 还没有构建镜像（执行 `./install.sh`，见第 3 节），或构建时用了别的镜像名（用 `--image` 指定） |
| `run.sh: 镜像里的用户是 …，当前用户是 …` | 镜像是为另一个用户构建的：当前用户执行 `./install.sh --tag 自己的镜像名` 另建一份，再用 `./run.sh --image` 指定 |
| `run.sh: 注意：没有发现手套串口` | Docker 低于 25，创建容器时手套没插上。插好后 `./run.sh --restart` |
| 容器里体检注明手套串口节点不可用、提示重建容器 | Docker 低于 25，手套是在容器创建之后插上或插拔过的：`./run.sh --restart` |
| `install.sh: 不要用 root 或 sudo 运行本脚本` | 以普通用户执行 `./install.sh`，需要 `sudo` 的步骤脚本会单独询问 |
| `install.sh: 在 … 里缺少这些发布文件`、`… 与 SHA256SUMS 对不上` | 按提示补齐或重新下载列出的文件，放在解开源码包的那个目录里（与 `SHA256SUMS` 同一目录） |
| `install.sh` 结尾提示注销并重新登录，`docker` 组才生效 | 刚把当前用户加入了 `docker` 组：本次构建已照常完成，注销并重新登录一次之前，按提示用 `sg docker -c './run.sh'` 代替 `./run.sh` |
| `install.sh: 基础镜像 … 不是 Ubuntu 22.04` | `--base-image` 指定的不是 Ubuntu 22.04 的镜像：换成 Ubuntu 22.04 的镜像（例如镜像站上的 `ubuntu:22.04`），或去掉 `--base-image` 用默认值 |
| `install.sh: … run.sh 用它创建容器失败` | 镜像本身的检查已通过，问题出在创建容器这一步：按提示里附带的 `run.sh` 输出处理，多半是 Docker 或主机设置的问题 |
| 构建时 pip 或 apt 下载超时 | 网络不稳定，重新执行 `./install.sh` 即可，已完成的步骤不会重做；国内网络加 `--mirror cn` |
| 容器里 `revohuman-lighthouses scan` 报 `蓝牙是必需的：…` | 容器创建时没加 `--ble`，或主机上的蓝牙服务没在运行：见第 7.1 节 |
| 容器里的窗口打不开，报 `cannot open display` 等 | 在主机桌面上打开的终端里执行 `./run.sh --restart`；通过 SSH 登录时改用无窗口模式 |
| 容器里的窗口能打开但很卡，启动时打印 `libGL error: failed to load driver` | 主机桌面由 NVIDIA 显卡输出，容器里只能用 CPU 绘制：改在主机上运行可视化，见第 8 节 |
| `run_sim_docker.sh` 报 `容器里的源码包（revohuman-0.1.0）没有 run_sim_host.sh` | 升级之前创建的容器还在运行，里面是之前版本的程序：确认容器里没有正在运行的程序后执行 `./run_sim_docker.sh --restart`（或 `docker/run.sh --restart`）重建容器。重建之后仍然这样，用主机上这份源码包执行 `./install.sh` 重新构建镜像 |
| 进入容器时打印 `groups: cannot find name for group ID …` | 不影响使用：`run.sh` 把主机上显卡、手套串口等设备的用户组带进容器，这些组在镜像里没有名字。用当前源码包的 `./install.sh` 构建的镜像不再打印 |
| 录制文件、配置在 `--restart` 之后不见了 | 写在了第 5 节表格之外的位置，容器重建时被清掉 |
| 其他错误码 | 与在主机上直接运行相同，见《07-日志与错误码》 |
