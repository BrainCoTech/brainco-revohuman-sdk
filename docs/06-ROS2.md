# 06 ROS 2

RevoHuman 提供三个 ROS 2 Humble 包，已在《01-环境安装与系统要求》第 8 节构建进 `~/ros2_ws`：

| 包 | 内容 |
|---|---|
| `revohuman_bringup` | launch 文件与默认参数 |
| `revohuman_ros` | 节点：`bimanual_node`（双手）、`glove_node`（单手） |
| `revohuman_msgs` | 自定义消息与服务 |

节点把手套关节角与 Tracker 位姿发布成 ROS 话题。P1 手套每只手 21 个关节，另有一只 Tracker；
P1 没有触觉与腕部相机，对应的话题不会出现。

## 1. 使用前

- 已按《01-环境安装与系统要求》装好全部软件，按《02-硬件连接》接好两只手套，
  并按《03-基站使用与配对》完成基站白名单与基站标定。
- **同一时间只能有一个程序打开手套与 Tracker。** ROS 节点运行时，不要同时运行 `revohuman-live`、
  《04-数据录制》的录制脚本或其他读手套的程序；反过来也一样。
- 每个新终端都会自动加载 ROS 与工作空间（第 01 章写进了 `~/.bashrc`），下文直接使用 `ros2` 命令。

## 2. 启动节点（终端 1）

把两只手套戴好或放稳，在终端 1 启动双手节点：

```bash
ros2 launch revohuman_bringup revohuman.launch.py
```

启动通常只要几秒；Tracker 要先收到基站信号，所以最长会等到 20 秒左右。终端里出现下面三行、最后一行是
`基站几何门：正常` 时表示已经就绪：

```text
[bimanual_node-1] [INFO] [1790552908.255867235] [revohuman.pair.bimanual_node]: left=/dev/ttyACM0 right=/dev/ttyACM1 触觉型号=none/none tactile_topics=off pair_mode=strict synchronized=True pair_accuracy_ms=0.0 calibration_srv=off
[bimanual_node-1] [INFO] [1790552910.049848790] [revohuman.pair.bimanual_node]: tracker left=LHR-XXXXXXXX right=LHR-XXXXXXXX lighthouses=['xxxxxxxx'] frame_id=world
[bimanual_node-1] [INFO] [1790552911.050623370] [revohuman.pair.bimanual_node]: 基站几何门：正常
```

第一行的 `synchronized=True` 表示两只手套的采样已硬件同步；第二行列出两只 Tracker 的序列号与在册基站。

保持终端 1 运行，下面的命令都在**终端 2** 里执行。要停止节点时在终端 1 按 `Ctrl+C`。

## 3. 查看数据（终端 2）

### 3.1 话题列表

```bash
ros2 topic list | grep revohuman
```

双手模式下应列出：

```text
/revohuman/pair/joint_states
/revohuman/pair/status
/revohuman/pair/tracker_delta_left
/revohuman/pair/tracker_delta_right
/revohuman/pair/tracker_pose_left
/revohuman/pair/tracker_pose_right
/revohuman/pair/tracker_status
```

`tracker_delta_left|right` 在还没有记过零位时也会列出，但没有数据，见第 4 节。

### 3.2 速率

关节角（按 `Ctrl+C` 结束）：

```bash
ros2 topic hz /revohuman/pair/joint_states
```

Tracker 位姿：

```bash
ros2 topic hz /revohuman/pair/tracker_pose_left
```

两条命令的输出末尾分别类似：

```text
average rate: 199.998
	min: 0.000s max: 0.015s std dev: 0.00051s window: 2205
```

```text
average rate: 249.840
	min: 0.002s max: 0.008s std dev: 0.00037s window: 2757
```

判断标准：关节角约 **200 Hz**，Tracker 位姿约 **250 Hz**（实测 249.5–249.9）。明显偏低时先确认没有别的程序在读手套，
再看第 3.5 节的状态。`ros2 topic hz` 自己也占 CPU，主机很忙时它报出的数字会比实际偏低。

### 3.3 关节角

```bash
ros2 topic echo --once /revohuman/pair/joint_states
```

示例输出（中间省略）：

```text
header:
  stamp:
    sec: 1790552972
    nanosec: 94947545
  frame_id: revohuman_pair
name:
- left_index_DIP_joint
- left_index_PIP_joint
- left_index_MCP_joint
- left_index_MPR_joint
- left_middle_DIP_joint
……
- left_thumb_CMR_joint
- left_thumb_CMP_joint
- right_index_DIP_joint
……
- right_thumb_CMP_joint
position:
- -0.6846926655573753
- 0.26284658535034605
……
velocity: []
effort: []
---
```

- `name` 共 42 项，前 21 项是左手、后 21 项是右手；
- `position` 的单位是**弧度**；
- `header.stamp` 是**采样时刻**（不是消息到达时刻），双手消息取左手的采样时刻。

### 3.4 Tracker 位姿

```bash
ros2 topic echo --once /revohuman/pair/tracker_pose_left
```

示例输出：

```text
header:
  stamp:
    sec: 1790552972
    nanosec: 990653991
  frame_id: world
pose:
  position:
    x: 0.009542217638544839
    y: -0.011296252865045958
    z: 0.0040065935434237965
  orientation:
    x: 0.21913929068019417
    y: 0.9378284251022679
    z: 0.21161747109497214
    w: -0.1663546280623118
---
```

`tracker_pose_left|right` 是 Tracker 在基站坐标系（定义见《03-基站使用与配对》第 5.3 节）里的绝对位姿，
`frame_id` 为 `world`（参数 `tracker_frame_id`）。位置单位米，姿态四元数按 ROS 惯例为 (x, y, z, w)，
`header.stamp` 同样是采样时刻。这里发的是原始位姿，没有经过 SDK 的遮挡恢复平滑。
节点不发布 tf：`world` 和 `revohuman_<手>_tracker_zero` 只是 header 里的名字，要接入 tf 树需要自己广播。

### 3.5 状态

状态话题每秒一条 JSON。它们的 QoS 是 **RELIABLE + TRANSIENT_LOCAL**，订阅时要写明，否则一条也收不到：

```bash
ros2 topic echo --once --qos-reliability reliable --qos-durability transient_local --field data /revohuman/pair/status
ros2 topic echo --once --qos-reliability reliable --qos-durability transient_local --field data /revohuman/pair/tracker_status
```

每条命令打印一行很长的 JSON。日常只需要看下面这些字段（括号里是一次正常运行的实测值）：

`/revohuman/pair/status`（手套）：

| 字段 | 含义 |
|---|---|
| `product.variant` / `product.complete` | 识别出的型号、传感器是否齐全（`P1` / `true`） |
| `effective_rate_hz`、`right.effective_rate_hz` | 左手、右手的实际帧率（均 `200.0`）。顶层的 `capture_gate`、`mapper_quality` 等是左手的，右手的同名字段在 `right` 下 |
| `capture_gate.open` | 时间戳门是否打开，`true` 才出数据（`true`）。刚启动时关闭几十毫秒是正常的 |
| `mapper_quality.stamp_trust` | 时间戳可信度（`trusted`）：`trusted` 正常；`coasting` 精度略降但仍在允许范围内，照常出数据；`untrusted` 时间戳不可信，时间戳门随之关闭，原因见《07-日志与错误码》第 3 节 N2104 |
| `stream_counters.frames_dropped_local` / `seq_gap_frames` | 主机侧丢帧 / 手套侧断档帧数（均 `0`） |
| `pairing.strict_sync_lost` | 双手硬件同步是否丢失（`false`） |
| `node.pairs_published` | 节点已发布的双手关节角条数 |

`/revohuman/pair/tracker_status`（Tracker 与基站）：

| 字段 | 含义 |
|---|---|
| `running` / `dead_reason` | Tracker 采集是否在运行（`true`）；停了时 `dead_reason` 写原因 |
| `trackers.<序列号>.healthy` / `pose_rate_hz` | 每只 Tracker 是否健康、位姿速率（`true` / 约 `249.8`） |
| `session.roles.left.online` / `session.roles.right.online` | 左、右 Tracker 是否在线（`true`） |
| `session.reference.ready` | 是否已有零位（见第 4 节） |
| `world.pose_watch` / `world.raw_watch` | 基站移动检测器是否在工作（`ok`）；不代表基站没动过。检测到移动时 `world.latched` 为 `true`；平移或水平转动检测不到（《03-基站使用与配对》第 8 节） |
| `lighthouses.declared` | 在册基站（《03-基站使用与配对》中登记的） |

## 4. Tracker 零位

`tracker_delta_left|right` 是 Tracker 相对**零位**的位姿增量。节点启动时沿用上一次记下的零位
（与《04-数据录制》的录制脚本共用同一份），没有零位时这两个话题不发布。

增量表达在零位那一刻 Tracker 自身的坐标系里（`frame_id` 为 `revohuman_<手>_tracker_zero`），与基站坐标系的原点、朝向无关。
重新标定基站后，存盘的零位不再沿用（带基站几何指纹），`tracker_delta_*` 会停发，要重新调 `tracker/set_reference`。

需要重新记零位时，把双手摆到零位姿势并保持静止，然后调用：

```bash
ros2 service call /revohuman/pair/tracker/set_reference std_srvs/srv/Trigger
```

示例输出：

```text
requester: making request: std_srvs.srv.Trigger_Request()

response:
std_srvs.srv.Trigger_Response(success=True, message='{"calibration_id": "ac92e87ed83449228d45546c8af53750", "baseline_m": null, "note": "单站：间距基线不适用", "path": "/home/<用户名>/.local/state/revohuman/tracker/calibration.json"}')
```

只用一台基站时 `baseline_m` 为 `null`、`note` 为「单站：间距基线不适用」，属正常；两台基站时 `baseline_m` 是两台基站的间距（米）。

`success=True` 表示零位已记下并存盘，下次启动节点自动沿用。之后确认增量话题在发布：

```bash
ros2 topic hz /revohuman/pair/tracker_delta_left
```

基站几何不达标时零位标定会被拒绝（`success=False`，`message` 里写明原因），按《03-基站使用与配对》处理。

## 5. 手套服务

读手套序列号与只读自检：

```bash
ros2 service call /revohuman/pair/left/get_sn std_srvs/srv/Trigger
ros2 service call /revohuman/pair/left/selftest std_srvs/srv/Trigger
```

示例输出：

```text
requester: making request: std_srvs.srv.Trigger_Request()

response:
std_srvs.srv.Trigger_Response(success=True, message='BCRH1PLXXXXXXXXXXX')

requester: making request: std_srvs.srv.Trigger_Request()

response:
std_srvs.srv.Trigger_Response(success=True, message='ok')
```

`get_sn` 返回手套序列号（左手以 `BCRH1PL` 开头），`selftest` 通过时返回 `ok`。

自检期间该手停止发数约 50 ms，**录制中不要调用**。右手把 `left` 换成 `right`。

## 6. 用 rosbag 录制

录下全部 RevoHuman 话题，录够后按 `Ctrl+C` 结束：

```bash
mkdir -p ~/revohuman_bags && cd ~/revohuman_bags
ros2 bag record -o demo -e '/revohuman/pair/.*'
```

查看录到的内容：

```bash
ros2 bag info ~/revohuman_bags/demo
```

示例输出（录了约 15 秒）：

```text
Files:             demo_0.db3
Bag size:          7.0 MiB
Storage id:        sqlite3
Duration:          14.870316709s
Start:             Sep 27 2026 23:49:44.274683357 (1790552984.274683357)
End:               Sep 27 2026 23:49:59.145000066 (1790552999.145000066)
Messages:          17873
Topic information: Topic: /revohuman/pair/joint_states | Type: sensor_msgs/msg/JointState | Count: 2974 | Serialization Format: cdr
                   Topic: /revohuman/pair/status | Type: std_msgs/msg/String | Count: 15 | Serialization Format: cdr
                   Topic: /revohuman/pair/tracker_delta_left | Type: geometry_msgs/msg/PoseStamped | Count: 3717 | Serialization Format: cdr
                   Topic: /revohuman/pair/tracker_delta_right | Type: geometry_msgs/msg/PoseStamped | Count: 3717 | Serialization Format: cdr
                   Topic: /revohuman/pair/tracker_pose_left | Type: geometry_msgs/msg/PoseStamped | Count: 3717 | Serialization Format: cdr
                   Topic: /revohuman/pair/tracker_pose_right | Type: geometry_msgs/msg/PoseStamped | Count: 3717 | Serialization Format: cdr
                   Topic: /revohuman/pair/tracker_status | Type: std_msgs/msg/String | Count: 16 | Serialization Format: cdr
```

核对方法：`Count` 除以 `Duration` 应接近各话题的速率——这里关节角 2974 / 14.87 s ≈ 200 Hz，Tracker 3717 / 14.87 s ≈ 250 Hz，
状态话题每秒一条。按每小时约 1.7 GB 预留磁盘（本例 7.0 MiB / 15 s 折算）。

- `-o` 指定的目录已存在时 `ros2 bag record` 会报错退出，换一个名字即可。
- bag 里每条消息自带的时间是**到达时刻**；做跨话题对齐请用消息里的 `header.stamp`（采样时刻），对齐方法见《09-时间戳同步》第 3 节。
- 需要同步健康度、零位等元数据时，用《04-数据录制》的 SDK 录制（MCAP 格式）。

## 7. 单手模式

只接一只手套时用单手模式。先在终端 1 按 `Ctrl+C` 停掉双手节点，再启动：

```bash
ros2 launch revohuman_bringup revohuman.launch.py mode:=left
```

右手用 `mode:=right`。单手的话题与服务在 `/revohuman/left`（或 `/revohuman/right`）下，名字不带左右后缀：

```bash
ros2 topic hz /revohuman/left/joint_states
```

输出末尾类似下面，同样约 200 Hz：

```text
average rate: 199.996
	min: 0.001s max: 0.009s std dev: 0.00034s window: 2207
```

单手节点启动时沿用双手模式记下的零位（终端 1 里有一行 `沿用落盘零位 …`），不需要重新记。

双手与单手不要同时启动：同一只手套只能被一个进程打开。

## 8. 参数

列出 launch 支持的全部参数：

```bash
ros2 launch revohuman_bringup revohuman.launch.py --show-args
```

参数写在命令行上，形如 `名字:=值`，例如 `mode:=left`。命令行优先于参数文件
`~/ros2_ws/src/revohuman_bringup/config/revohuman.yaml`，参数文件优先于节点默认值。
P1 常用参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `mode` | `pair` | `pair` 双手；`left` / `right` 单手 |
| `product` | `auto` | 型号，自动识别；也可写 `P1` |
| `rate_hz` | `200.0` | 手套发布速率（Hz） |
| `pair_mode` | `strict` | `strict`：只输出同一硬件同步周期的双手对子；`best_effort`：允许 1 ms 内的对子 |
| `tracker_mode` | `required` | `required`：Tracker 起不来就拒绝启动；`auto`：起不来时只发手套；`off`：不用 Tracker |
| `tracker_frame_id` | `world` | `tracker_pose*` 的 `frame_id` |
| `tracker_geometry_gate_mode` | `error` | 基站几何不达标时拒绝零位标定 |
| `allow_calibration` | `false` | 是否注册手套编码器标定服务（会写设备，平时保持关闭） |
| `log_level` | `info` | 节点日志级别 `debug` / `info` / `warn` / `error` |

## 9. 话题与服务一览

### 9.1 话题

| 双手（`/revohuman/pair/`） | 单手（`/revohuman/left/` 或 `/right/`） | 类型 | 说明 |
|---|---|---|---|
| `joint_states` | `joint_states` | `sensor_msgs/JointState` | 双手 42 关节（左 21 + 右 21）/ 单手 21 关节，弧度 |
| `tracker_pose_left` / `tracker_pose_right` | `tracker_pose` | `geometry_msgs/PoseStamped` | 基站坐标系中的绝对位姿 |
| `tracker_delta_left` / `tracker_delta_right` | `tracker_delta` | `geometry_msgs/PoseStamped` | 相对零位的增量，`frame_id` 为 `revohuman_<手>_tracker_zero`；有零位才发布 |
| `status` | `status` | `std_msgs/String` | 1 Hz 手套状态 JSON |
| `tracker_status` | `tracker_status` | `std_msgs/String` | 1 Hz Tracker 状态 JSON |

- 数据话题 QoS：BEST_EFFORT，depth 10。
- 状态话题 QoS：RELIABLE + TRANSIENT_LOCAL，depth 1；订阅方 QoS 不匹配时一条也收不到。
- 所有 `header.stamp` 都是采样时刻。

### 9.2 服务

| 服务（双手在 `/revohuman/pair/left/` 与 `/revohuman/pair/right/` 下，单手在 `/revohuman/<手>/` 下） | 类型 | 说明 |
|---|---|---|
| `get_sn` | `std_srvs/srv/Trigger` | 读手套序列号 |
| `selftest` | `std_srvs/srv/Trigger` | 只读自检，该手停流约 50 ms |

| 服务（在 `/revohuman/pair/` 或 `/revohuman/<手>/` 下） | 类型 | 说明 |
|---|---|---|
| `tracker/set_reference` | `std_srvs/srv/Trigger` | 记零位并存盘 |
| `tracker/get_status` | `std_srvs/srv/Trigger` | 返回 Tracker 状态 JSON |
| `tracker/set_calibration_mode` | `std_srvs/srv/SetBool` | 进入基站标定（基站标定请按《03-基站使用与配对》用命令行完成） |

## 10. 节点的启动与重启

- 节点启动时**不做**基站启动检查，也不自动记零位：它沿用上一次存盘的零位。基站是否达标看
  `tracker_status` 里的 `geometry`，基站被挪动时节点日志打 ERROR 并停止 Tracker 数据（平移或水平转动检测不到，见《03-基站使用与配对》第 8 节），
  此时按《03-基站使用与配对》重新标定基站后重启节点。节点的运行期检测比 SDK 少，基站动过就重新标定，不要等节点报错。
- 节点以退出码 5 退出表示切换 Tracker 模式（运行 ↔ 基站标定），launch 会自动把它重新拉起；
  60 秒内重启超过 10 次则不再重启。

## 11. 常见问题

| 现象 | 处理 |
|---|---|
| `Package 'revohuman_bringup' not found` | 当前终端没有加载工作空间：打开一个新终端再试，或执行 `source ~/ros2_ws/install/setup.bash` |
| `ros2 topic list` 里没有 `/revohuman/...` | 节点没启动或已退出，看终端 1 的日志；两个终端的 `ROS_DOMAIN_ID` 必须相同 |
| 终端 1 报「left 手的手套不在位」（或 right） | 这只手套没接好，按《02-硬件连接》第 3 节检查；只接了一只手套时用单手模式（第 7 节） |
| 终端 1 报手套串口被占用 | `revohuman-live`、录制脚本或另一个 ROS 节点正在使用手套，先关掉它 |
| 终端 1 报 `tracker 启动失败` 后退出 | Tracker 没接好或基站没配好：按《03-基站使用与配对》检查；只想先看手套数据时加 `tracker_mode:=auto` |
| `ros2 topic echo` 状态话题没有输出 | 没写 `--qos-reliability reliable --qos-durability transient_local` |
| 没有 `tracker_delta_*` 话题 | 还没记过零位：调用 `tracker/set_reference`（第 4 节） |
| `set_reference` 返回 `success=False` | 看 `message` 里的原因；基站几何不达标时按《03-基站使用与配对》重新标定 |
