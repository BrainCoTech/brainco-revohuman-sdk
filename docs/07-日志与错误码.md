# 07 日志与错误码

本章说明 RevoHuman 各程序的日志写在哪里、运行中的提示码（N 码）与异常错误码的含义，
以及遇到问题时如何收集信息。只涉及 P1 手套。

## 1. 日志在哪里

| 程序 | 日志去向 |
|---|---|
| `python3 -m revohuman …`、`revohuman-lighthouses …` 命令行 | 打印在终端（标准错误）；加 `-v` 打开调试日志，`-v` 写在子命令之前 |
| `revohuman-live`（《05-仿真与可视化》） | 打印在启动它的终端；加 `-v` 打开调试日志 |
| 自己写的 Python 程序（如《04-数据录制》的脚本） | 由程序里的 `logging` 设置决定；SDK 的日志记录器名都以 `revohuman` 开头 |
| ROS 2 节点（《06-ROS2》） | 打印在运行 `ros2 launch` 的终端，同时写进 `~/.ros/log/` |
| 三维可视化 `run_viewer.sh` | 打印在启动它的终端 |
| Tracker 与基站的状态文件 | `~/.local/state/revohuman/tracker/`（设了 `XDG_STATE_HOME` 时在 `$XDG_STATE_HOME/revohuman/tracker/`），用 `python3 -m revohuman tracker status` 查看（见《03-基站使用与配对》） |
| 基站几何 | `~/.config/libsurvive/config.json`，由基站标定写入，不要手动修改或删除 |

把一次命令的完整日志存进文件（调试级别）：

```bash
python3 -m revohuman -v doctor 2>&1 | tee ~/revohuman-doctor.log
```

### 1.1 日志的颜色

在终端里运行 `python3 -m revohuman`、`revohuman-live`、`revohuman-lighthouses` 与三维可视化时，日志按级别显示为不同颜色，
整条日志连同异常堆栈一起上色（第 3 节的 N 码也按各自的级别上色）：

| 级别 | 颜色 |
|---|---|
| DEBUG（加 `-v` 时才有） | 暗淡 |
| INFO | 不上色 |
| WARNING | 黄色 |
| ERROR | 红色 |
| CRITICAL | 红色加粗 |

由环境变量 `REVOHUMAN_LOG_COLOR` 控制，取值不区分大小写，其他取值按 `auto` 处理：

| 取值 | 效果 |
|---|---|
| `auto`（默认） | 输出是终端、没有设置 `NO_COLOR`、`TERM` 不是 `dumb` 时上色 |
| `always` | 总是上色，不看 `NO_COLOR`。例如 `REVOHUMAN_LOG_COLOR=always python3 -m revohuman -v doctor 2>&1 \| less -R` 翻看带颜色的日志 |
| `never` | 不上色 |

- 输出重定向到文件或管道时（例如上面的 `tee`）不带颜色，内容与不上色时逐字节相同，本章的示例输出都是这种形式。
- 自己写的 Python 程序里，日志的格式与颜色由程序自己的 `logging` 设置决定，SDK 不给它上色。
- ROS 2 节点的日志由 ROS 2 自己上色，不受 `REVOHUMAN_LOG_COLOR` 与 `NO_COLOR` 控制：
  `ros2 run` 直接在终端里运行时上色，`ros2 launch` 启动时不上色；设置 `RCUTILS_COLORIZED_OUTPUT=1` 强制上色，`=0` 关闭。

## 2. 反馈问题时收集的信息

反馈问题时，请在接好手套的状态下执行下面的命令，把生成的 `~/revohuman-report.tgz` 与出问题时终端里的输出一并提供：

```bash
cd ~
python3 -m revohuman doctor --json > revohuman-doctor.json
python3 -m revohuman tracker status > revohuman-tracker-status.txt 2>&1
tar czf revohuman-report.tgz revohuman-doctor.json revohuman-tracker-status.txt .local/state/revohuman/tracker .config/libsurvive/config.json
ls -l revohuman-report.tgz
```

压缩包里有手套体检结果、Tracker 与基站的状态（含在册基站）与标定状态、基站几何，不含录制数据。

## 3. 运行期提示（N 码）

SDK 在运行中遇到的情况（时间基准变化、双手同步、USB 链路、重连、录制作废等）以日志形式报告，每条都以 `N` 加四位数字开头，
方括号里是涉及的串口：

```text
2026-09-27 23:51:04,376 INFO revohuman.glove: N2104 [/dev/ttyACM0] 时间戳质量降为 untrusted（时间基准未就绪）
2026-09-27 23:51:04,408 INFO revohuman.glove: N2105 [/dev/ttyACM0] 时间戳质量恢复为 trusted
2026-09-27 23:51:04,408 INFO revohuman.glove: N2101 [/dev/ttyACM0] 录制门已开，开始出帧
```

按开头的码判断即可，不必解析后面的中文。提示里的「录制门」即其他章节所说的时间戳门。P1 会用到的提示码：

| 码 | 级别 | 含义 |
|---|---|---|
| N2101 | INFO | 录制门已开，开始出帧 |
| N2102 | WARNING | 录制门关（附原因），帧暂停派发，门开后自动恢复 |
| N2103 | INFO | 录制门重开（附关闭时长与期间拦下的帧数） |
| N2104 | WARNING | 时间戳质量降级（附原因）。刚打开手套时每只手出现一次 `untrusted（时间基准未就绪）`，级别为 INFO，是正常的 |
| N2105 | INFO | 时间戳质量恢复 |
| N2106 | WARNING | 时间基准建立未完成，正在重试 |
| N2107 | WARNING | 手套到主机的传输延迟异常 |
| N2201 | WARNING | 双手硬件同步未建立，退回软件配对（配对精度下降） |
| N2202 | ERROR | 双手硬件同步已失去 |
| N2203 | WARNING | 双手硬件同步已重建 |
| N2204 | ERROR | 双手硬件同步重建失败 |
| N2205 / N2206 | WARNING / INFO | 双手采样对齐偏差超出预算 / 已恢复 |
| N2301 | WARNING | USB 链路不稳，时间戳暂不可信 |
| N2302 / N2303 / N2304 | WARNING / WARNING / INFO | USB 链路复位中 / 恢复失败 / 已恢复 |
| N2401 / N2402 | WARNING | 重连失败、退避重试中 / 流已恢复 |
| N2403 | WARNING | 串口换号（USB 重新枚举），已自动重新定位 |
| N2404 | WARNING | 流中断，重连中 |
| N2405 | ERROR | 固件不兼容，流已关闭且不再重连，需要升级手套固件 |
| N2406 | WARNING | 手套固件不支持在采集期间上报按键，按键不可用，数据采集不受影响。只在显式开启按键（`button=True`）时出现 |
| N2501 | ERROR | 整条录制作废（附原因与文件路径），见《04-数据录制》 |
| N2502 | ERROR | 录制因双手严格同步丢失而中止 |

时间质量相关的提示只报原因大类：

| 原因 | 含义 | 处置 |
|---|---|---|
| `clock_not_ready` | 时间基准尚未建立或已过期，正在重建 | 通常数秒内自愈，无需操作 |
| `clock_degraded` | 时间基准质量下降 | 持续出现时检查 USB 线缆与主机负载 |
| `host_clock_event` | 主机时钟跳变（休眠唤醒、手动改时间、对时步进） | 自动恢复；录制中避免 |
| `device_reset` | 手套复位 | 自动恢复；频繁出现时检查供电 |
| `link_unstable` | USB 链路不稳 | 检查线缆与供电，手套直接插主机 |

时间戳门、双手同步各提示码的现象、SDK 的自动处理与你要做什么，见《09-时间戳同步》第 6 节。

### 3.1 把提示码写成 JSON

每条提示日志还带有结构化字段：`record.revohuman_code`（如 `"N2101"`）与 `record.revohuman_fields`（串口、手别、次数、时长等）。
下面的程序打开两只手套运行指定的秒数，把收到的提示按每行一条 JSON 写进文件。保存为 `~/revohuman_notices.py`：

```python
"""打开 P1 两只手套运行指定秒数，把 RevoHuman 运行期提示（N 码）按 JSON 行写进文件。

用法：python3 ~/revohuman_notices.py <秒数> [输出文件，默认 ~/revohuman-notices.jsonl]
"""
import json
import logging
import os
import sys
import time

from revohuman import RevoHumanError, error_code, format_error, open_kit


class NoticeJsonLines(logging.Handler):
    """只收带提示码的日志，每条写一行 JSON。"""

    def __init__(self, path):
        super().__init__()
        self.file = open(path, "a", encoding="utf-8")

    def emit(self, record):
        code = getattr(record, "revohuman_code", None)
        if code is None:
            return
        line = {
            "time": record.created,
            "level": record.levelname,
            "code": code,
            "fields": getattr(record, "revohuman_fields", {}),
            "text": record.getMessage(),
        }
        self.file.write(json.dumps(line, ensure_ascii=False, default=str) + "\n")
        self.file.flush()


def main():
    if len(sys.argv) not in (2, 3):
        print(__doc__.strip(), file=sys.stderr)
        return 2
    seconds = float(sys.argv[1])
    path = sys.argv[2] if len(sys.argv) == 3 else os.path.expanduser("~/revohuman-notices.jsonl")
    logging.basicConfig(level=logging.INFO, format="%(asctime)s %(levelname)s %(name)s: %(message)s")
    logging.getLogger("revohuman").addHandler(NoticeJsonLines(path))
    try:
        with open_kit("P1", sensors={"encoder"}) as kit:
            print(f"已打开 {kit.hands}，运行 {seconds:g} 秒")
            time.sleep(seconds)
    except RevoHumanError as exc:
        print(f"打开失败：{format_error(exc)}（错误码 {int(error_code(exc))}）", file=sys.stderr)
        return 1
    print(f"提示已写入 {path}")
    return 0


if __name__ == "__main__":
    sys.exit(main())
```

运行 5 秒并查看结果：

```bash
python3 ~/revohuman_notices.py 5
cat ~/revohuman-notices.jsonl
```

示例输出（前面是打开手套时终端里的日志，从略；`cat` 出的文件每只手套各有 N2104 → N2105 → N2101 三条，这里只列左手）：

```text
已打开 [<Handedness.LEFT: 'left'>, <Handedness.RIGHT: 'right'>]，运行 5 秒
提示已写入 /home/<用户名>/revohuman-notices.jsonl
{"time": 1790553064.376964, "level": "INFO", "code": "N2104", "fields": {"state": "untrusted", "cause": "时间基准未就绪", "port": "/dev/ttyACM0"}, "text": "N2104 [/dev/ttyACM0] 时间戳质量降为 untrusted（时间基准未就绪）"}
{"time": 1790553064.408402, "level": "INFO", "code": "N2105", "fields": {"state": "trusted", "port": "/dev/ttyACM0"}, "text": "N2105 [/dev/ttyACM0] 时间戳质量恢复为 trusted"}
{"time": 1790553064.4084709, "level": "INFO", "code": "N2101", "fields": {"port": "/dev/ttyACM0"}, "text": "N2101 [/dev/ttyACM0] 录制门已开，开始出帧"}
```

文件是追加写的，多次运行会累积。

`sensors={"encoder"}` 表示只打开手套、不启动 Tracker，所以几秒就能打开。

## 4. 错误码

程序出错时抛出的异常都继承 `revohuman.RevoHumanError`。`revohuman.error_code(exc)` 给出数字错误码，
`revohuman.format_error(exc)` 给出带码的可读文本（上一节的程序就是这样打印的）。命令行工具报错时只打印文字说明，不带码。

| 码 | 异常 | 场景 | 处理 |
|---:|---|---|---|
| 1000 | `RevoHumanError` | 通用错误 | 看文字说明 |
| 1100 | `TransportError` | 与手套的 USB 通信出错 | 检查 USB 连接，重新插拔手套后重试 |
| 1101 | `Disconnected` | 连接断开 / 订阅已关闭 | 检查 USB 连接后重新打开 |
| 1102 | `PortBusyError` | 手套串口被其他程序占用（附占用者的进程号） | 关掉占用手套的程序（`revohuman-live`、录制脚本、ROS 节点等） |
| 1200 | `ProtocolError` | 手套应答不符合通信协议 | 重新插拔手套后重试；仍出现时按第 2 节收集信息后联系技术支持 |
| 1201 | — | 手套应答异常 | 重新插拔手套后重试 |
| 1202 | `UnsupportedFeatureError` | 固件不支持该功能 | 升级手套固件 |
| 1203 / 1204 | `TimeProbeUnsupported` / `TimeProbeIncompatible` | 固件不支持 / 不兼容时间同步功能 | 升级手套固件 |
| 1205 | `FirmwareIncompatible` | 固件版本不兼容 | 升级手套固件 |
| 1300 | `CalibrationError` | 手套关节零位标定失败，或只有部分编码器成功 | 手套五指伸直平放、保持不动，重新执行 `python3 -m revohuman glove calibrate --hand left`（右手换成 `right`），见《02-硬件连接》第 5 节 |
| 1400 | `UnregisteredGloveError` | 手套的 MCU 序列号认不出是左手还是右手（例如两只手套序列号相同） | 改按串口指定：`firmware`、`glove calibrate` 加 `--port`，程序里传 `port=` / `connect_pair(left_port=, right_port=)`，ROS 2 节点设参数 `port` / `left_port`、`right_port`（不是 launch 参数，要写进 `params_file` 或用 `ros2 run … --ros-args -p` 传）；仍不确定时按第 2 节收集信息后联系技术支持 |
| 1401 | `GloveNotPresent` | 要打开的那只手的手套没插（例如默认打开双手、只插了一只） | 插上那只手套；只用一只手时命令行加 `--hands left` 或 `--hands right` |
| 1500 | `StreamRateConflict` | 同一只手套被以不同速率重复订阅 | 程序里统一速率 |
| 1600 | `CaptureGateClosed` | 时间戳门关闭时开始录制 | 等门开（N2101 / N2103）后再开始，见《04-数据录制》 |
| 1700 | `StrictSyncLost` | 双手硬件同步丢失、录制器已中止后又开始录制（见《09-时间戳同步》第 6.3 节） | 检查两只手套的 USB 连接，重新打开设备后再录 |
| 1800 | `TactileUnsupported` | 程序要求触觉（`require_tactile=True`），但这只手套的型号不带触觉 | 换带触觉的手套，或不要求触觉 |
| 1801 | `TactileUndetermined` | 还判不出这只手套带不带触觉（设备信息未读出，或固件还在探测外设） | 稍等后重试 |
| 1802 | `VariantMismatch` | 左右两只手套型号不一致（一只带触觉、一只不带） | 换成同型号的一对 |
| 1803 | `ProductUnidentified` | 判不出型号 | 按第 2 节收集信息后联系技术支持 |
| 1804 | `ProductMismatch` | 声明的型号与在位硬件不符，或缺少应有的传感器（如 Tracker 没接） | 检查两个手套单元是否接全，见《02-硬件连接》 |
| 1900 | `TrackerBusyError` | Tracker 已被其他程序占用 | 关掉占用 Tracker 的程序 |
| 1901 | `TrackerStreamDead` | 启动后收不到 Tracker 数据，或运行中断流 | 检查 Tracker 连接、设备权限与基站，见《03-基站使用与配对》 |
| 1902 | `WorldFrameChanged` | 采集中基站被移动，或白名单以外的基站被解进了坐标系 | 基站被移动：固定好基站，重新标定后重新启动程序；外来基站：关掉它或移出视野后重新启动程序 |
| 1903 | `LighthouseError` | 基站白名单、信道预检或基站写操作不通过（逐条列出原因） | 按原因处理，见《03-基站使用与配对》 |
| 1904 | `CalibrationRejected` | 基站标定或零位标定被拒绝、未完成 | 按原因处理，见《03-基站使用与配对》 |
| 1905 | `TrackerNotReady` | Tracker 启动检查不通过（附原因与处置） | 按提示处理，见《03-基站使用与配对》 |
| 1906 | `GeometryLost` | 采集中基站几何丢失 | 按提示处理，见《03-基站使用与配对》 |

### 4.1 例：手套被占用（1102）

同一时间只能有一个程序打开手套。在终端 1 启动广播，只打开手套：

```bash
revohuman-live --no-tracker
```

广播运行时，在终端 2 再打开手套：

```bash
python3 ~/revohuman_notices.py 3 || echo "退出码 $?"
```

示例输出：

```text
2026-09-27 23:51:25,532 INFO revohuman.manager: left 手 → 单元 1-1 串口 /dev/ttyACM0（按 serial 定位）
2026-09-27 23:51:25,534 INFO revohuman.manager: right 手 → 单元 3-1 串口 /dev/ttyACM1（按 serial 定位）
打开失败：E1102 PortBusyError: 串口 /dev/ttyACM0 已被其他进程独占（占用进程 pid=144）（错误码 1102）
退出码 1
```

`pid=` 后面是占用手套的进程号，可以用 `ps -p <进程号> -o pid,cmd` 看是哪个程序。

在终端 1 按 `Ctrl+C` 停止广播后，再运行就能正常打开。

## 5. 命令行退出码

`python3 -m revohuman …`：

| 退出码 | 含义 |
|---|---|
| 0 | 成功 |
| 1 | 失败、未就绪，或被 Tracker 启动检查拦下 |
| 2 | 用法错误（参数写错），或工具本身出错（如蓝牙不可用） |
| 3 | 被拒绝，或型号不符 |

`revohuman-live`（与 `python3 -m revohuman live` 相同）：打印 `广播中` 之后按 `Ctrl+C` 结束，退出码 `0`；
还没打印 `广播中` 就按 `Ctrl+C`，退出码 `130`；手套打不开、`--product` 与在位硬件不符、广播 socket 用不了，退出码 `2`。
Tracker 打不开不影响退出码：`revohuman-live` 打印原因后照常广播手套数据。

`revohuman-lighthouses` 的退出码：`0` 成功；`1` 有缺口或冲突、计划还没执行，或写入基站失败；`2` 蓝牙不可用或被占用，或用法错误。ROS 2 节点以退出码 5 退出表示切换 Tracker 模式，由 launch 自动重启，见《06-ROS2》。

## 6. 常见问题

| 现象 | 处理 |
|---|---|
| 报 `LIBUSB_ERROR_ACCESS` 或 `libusb couldn't open USB device … Permission denied`，随后报 `TrackerStreamDead`（1901） | Tracker 的设备规则没装或没生效：按《01-环境安装与系统要求》第 6 节安装规则，执行 `sudo udevadm control --reload-rules && sudo udevadm trigger`，再重新插拔手套 |
| 报 `Permission denied: '/dev/ttyACM0'` | 当前用户不在 `dialout` 组：按《01-环境安装与系统要求》第 5 节加入，并注销后重新登录 |
| 提示里的命令写作 `python -m revohuman …`，执行时报 `python: command not found` | Ubuntu 22.04 的命令是 `python3`，把 `python` 换成 `python3` 再执行 |
| `revohuman-live: command not found` | `~/.local/bin` 不在 `PATH` 里：打开一个新终端再试（见《01-环境安装与系统要求》第 7 节） |
| 日志里反复出现 N2301 / N2404 | USB 链路不稳：换线、不经过 HUB、检查主机供电 |
| 录制时出现 N2501 | 该段数据作废，见《04-数据录制》 |
